# Тестовое задание: Python разработчик (ТОЛЬКООПТ)

## Запуск
```
python starter.py                    # пример из задания: 4728.00 / APPLY
python -m unittest -v test_starter   # тесты
```

Тесты совместимы с pytest: `pytest test_starter.py`.

---

## 1. Вопросы к задаче

1. Какую ошибку считаем более дорогой: потерю продаж из-за завышенной цены или потерю маржи из-за заниженной?
2. Для всех ли клиентов и позиций нужно автообновление или только для части (категории, топ-SKU)? Нужна ли ручная проверка перед публикацией?
3. Что сейчас делают с Excel с 20 площадок и как проверяют качество данных?
4. Насколько критична часовая частота? Что должно происходить, если часть данных пришла с опозданием или одна площадка недоступна?
5. Кто принимает решение «цена верна» и кто реагирует на инциденты вне рабочего времени?

**Два главных вопроса**

- **№1 (цена ошибки).** Определяет, насколько консервативной будет защита: пороги `REVIEW`, нижняя граница цены, требования к свежести и числу источников. Допущение: заниженная цена хуже упущенной продажи, поэтому при сомнении цена не меняется (`HOLD`).
- **№2 (объём автоматизации).** Определяет способ внедрения. Допущение: начинаем с части позиций и режима «рекомендации без публикации» параллельно со старой системой, затем расширяем.

---

## 2. Архитектура

**Путь данных**

1. Планировщик раз в час запускает сбор по каждой площадке отдельно.
2. Сборщик сохраняет сырые ответы и нормализованные предложения в БД вместе с `run_id`, временем и статусом площадки.
3. Валидатор решает, пригодны ли данные для расчёта.
4. Расчётчик применяет правила из `recommend_price` и пишет рекомендацию с решением `APPLY` / `REVIEW` / `HOLD` и причиной.
5. Публикатор передаёт в клиентский прайс только `APPLY`. `REVIEW` попадает в очередь ручной проверки, `HOLD` оставляет цену без изменений.


**Внедрение рядом со старой системой и откат**

1. Теневой режим: новая система считает, но ничего не публикует; результат сравнивается со старым прайсом.
2. Публикация для небольшой доли позиций за флагом.
3. Постепенное расширение.

Откат: выключение флага. Старая система продолжает работать, мы её не трогали.

---

## 3. Исправления в `recommend_price`

- Добавлены тайм-аут `asyncio.wait_for(..., timeout_s)` и обработка исключений источника; при сбое, тайм-ауте или `status != success` возвращаются текущая цена и `HOLD`.
- Вместо `float` везде `Decimal`; цена конкурента умножается на `0.985` и округляется вниз до копейки.
- Предложения с `delivery_days is None` или больше 6 дней отбрасываются; `MYSHOP` исключается в любом регистре.
- Если подходящих предложений нет: текущая цена и `HOLD`, даже если она ниже `min_price`.
- Рекомендация не ниже `min_price`.
- Отклонение от текущей цены более чем на 30% даёт `REVIEW`; ровно 30% остаётся `APPLY`. Сравнение выполняется в `Decimal`.

Тесты (`test_starter.py`) покрывают обычный расчёт, округление вниз, нижнюю границу `min_price`, границу 30% (ровно и чуть больше), тайм-аут, исключение источника, статусы `partial` и `error`, отсутствие подходящих предложений и исключение собственного магазина.
